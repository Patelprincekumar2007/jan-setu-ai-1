# NagrikLens AI: Technical Architecture Specification

## 1. Overview & Prototype Scope
NagrikLens AI is a multilingual citizen development intelligence platform designed as a decision-support prototype for public administration officers. It is NOT an official government grievance portal, government-operated software, or government-endorsed system. It is a hackathon prototype demonstrating evidence-backed civic decision support.

## 2. Core Information Separation
The platform enforces a strict separation between three distinct data domains:
1. **Citizen Data:** Unverified issues and requests submitted directly by citizens.
2. **Public Source Data:** Verified open datasets ingested from official repositories (e.g. data.gov.in, Ministry of Jal Shakti) under open licenses (e.g. GODL).
3. **AI Interpretation:** Structured parameters and summaries generated by Google Gemini models.

Public data is never presented as citizen submissions, and AI inferences are never represented as official government statistics.

### Data Pipeline
```
Raw CSV / Open Source
    ↓
Loader (BaseDatasetLoader)
    ↓
Deterministic Normalizer
  - Geographic standardisation (whitespace collapse, standard title-casing)
  - Strict numeric conversion (preserves nulls, rejects synthetic zeroes)
  - Civic sector category mapping (Water, Roads, Healthcare, Sanitation, Other)
  - Missing field handling (null preservation)
    ↓
Pydantic Schema Validation (DatasetCreate, PublicDataRecordCreate)
    ↓
SQLite Persistence (datasets, public_data_records)
    ↓
Public REST API (/api/datasets, /api/datasets/{id}/records)
```

### Architecture Pipeline
```
PublicDataRecord + Dataset Metadata
    ↓
Deterministic Evidence Builder (build_knowledge_evidence)
  - Generates factual grounding sentence:
    "District Dharashiv, Maharashtra recorded rural tap water coverage of 50.76%..."
  - Preserves complete provenance (dataset_id, record_id, source_name, source_reference, source_url)
    ↓
Pydantic Validation (KnowledgeEvidenceCreate)
    ↓
Idempotent SQLite Persistence (knowledge_evidence table)
    ↓
Abstract Retrieval Contract (BaseKnowledgeRetriever)
    ↓
Deterministic Baseline Implementation (DeterministicMetadataRetriever)
    ↓
Semantic FAISS Vector Index (search_vector_index using SentenceTransformers)
    ↓
Read-only Retrieval API (GET /api/knowledge/search, GET /api/knowledge/semantic-search, GET /api/knowledge/datasets/{id})
```

### Retrieval Contract Specification
The `BaseKnowledgeRetriever` abstract class defines the standard method `retrieve(query, *, state, district, category, top_k)`. In Step 3C-1, the active retriever was `DeterministicMetadataRetriever`. It provides exact/partial administrative matching.

### Semantic FAISS Vector Index (Step 3C-2A)
The `backend.knowledge.vector_index` module provides an implementation for generating and querying semantic embeddings.
- Uses `sentence-transformers` (default: `paraphrase-multilingual-MiniLM-L12-v2`).
- Vectors are L2 normalized, enabling cosine similarity via FAISS `IndexFlatIP`.
- Local index (`knowledge.index`) and metadata (`knowledge_metadata.json`) are persisted deterministically.
- Includes automated index staleness detection based on evidence hashing and model metadata matching.

> **Important Disclosure:** Generative RAG generation based on these retrieved vector contexts is NOT yet active. The semantic index currently acts only as an available retriever.
